# Interpreting verify output and report summaries

## Verify output

`chart-verifier verify <chart-uri>` prints the result of each check and an overall result, and can emit JSON or YAML (`--output json|yaml`) and write a report file (`--write-to-file`, producing `chartverifier/report.yaml`).

Per-check outcomes and what to do next:

- **Positive / passed** - the check succeeded. No action needed.
- **Negative / failed** - the check found a problem. The output names the check and, in the error log, a remedial action. Suggest fixing the chart (e.g. add `README.md` for `has-readme`, add `values.schema.json` for `contains-values-schema`) and re-running that check with `--enable <check>`.
- **Skipped / inapplicable** - the check did not apply or was not run, for example a check disabled via `--disable`, a prerequisite not met, or a check that requires a cluster when none was used. In `report results` output, checks omitted by a targeted subset appear as "Missing mandatory check" messages and count toward the `failed` total even though they never ran - treat them as skipped, not failed. Tell the user which checks were skipped and why; if the skip was caused by missing prerequisites (cluster, credentials, network), offer to re-run with the prerequisite in place - after asking.
- **Command error** - the CLI itself failed (bad chart URI, unreachable remote, malformed chart archive, missing `helm` binary, cluster connection failure). The error text and the error log (`chartverifier/verifier-<timestamp>.log`) identify the cause. Suggest the concrete fix: correct the URI, download the chart locally, install prerequisites, or use an appropriate `--kube-context`.

## Report summaries

`chart-verifier report {all,metadata,annotations,digests,results} <report-file>` summarizes an existing report:

- `metadata` - chart name, version, and other `Chart.yaml` facts.
- `annotations` - chart annotations relevant to certification (e.g. `charts.openshift.io/name`, certified OpenShift versions).
- `digests` - the report's digests (chart digest, package digest).
- `results` - per-check outcomes with the overall result.
- `all` - everything above.

Set the profile vendor/version with `--set` when the user requests it.

Digest validation is on by default: the CLI checks that the digest recorded in the report matches the report content, which protects against edited or corrupted reports.

- **Digest mismatch outcome** - the `report` command fails with a digest mismatch error when the report file has been modified since it was written. Do not paper over it: tell the user the report's integrity cannot be confirmed and the report should be regenerated by re-running `verify`. Only bypass with `--skip-digest-check` if the user explicitly requests it. This flag is for testing purposes only.
